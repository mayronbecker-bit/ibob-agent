rule_validator.py — Claude sugere, regras Python decidem

Princípio fundamental: Claude API nunca tem acesso direto ao Execution Engine. O fluxo é sempre:
Claude → rule_validator.py → proposals table → aprovação humana → executor.py
Se a regra bloqueia, a proposta não existe — independente do que o Claude sugeriu.
EtapaO que validaSe falha
1. Schema validationJSON do Claude tem estrutura válida e todos os campos obrigatóriosDescarta proposta inteira · log de schema_error
2. Guardrail checkBudget +30%/dia · campanha <7 dias · sem margem Orbita · estoque · trackingDescarta a ação específica · motivo registrado
3. Budget gateaction_type == budget_change exige approved_by = mayron explícito no bancoNão cria proposta de budget · bloqueio programático
4. Threshold checkValores propostos dentro dos thresholds da versão ativa em agent_configAjusta para o limite ou descarta
5. Conflict checkHierarquia Tracking > Estoque > Margem > Performance · remove conflitosRemove proposta de menor prioridade
6. Proposta criadaSó após todos os checks passaremGrava em proposals com status=pending

Claude PODE fazer

  • Analisar métricas e identificar anomalias
  • Sugerir ações dentro dos guardrails
  • Gerar texto de proposta para o time
  • Consultar histórico da Memória de Decisão
  • Recomendar prioridade entre campanhas
  • Explicar o raciocínio de cada sugestão

Claude NÃO PODE fazer

  • Chamar APIs do Google Ads ou Meta diretamente
  • Escrever em proposals sem passar pelo rule_validator
  • Alterar thresholds ou guardrails
  • Acessar tokens de autenticação
  • Executar qualquer ação sem aprovação no banco
  • Bypassar o budget gate mesmo com justificativa

Budget Gate — proteção programática no executor.py (não é só UI):
Antes de qualquer chamada de API com budget, o executor verifica no banco:
1. proposal.action_type == 'budget_change'
2. proposal.approved_by == 'mayron@ibob.com.br'
3. proposal.approved_at IS NOT NULL
4. agent_state.dtl_blocked == false
Se qualquer condição falhar → execução abortada + log de tentativa bloqueada.

Versionamento de prompts e thresholds — agent_versions

Política: Cassiano pode propor mudança de threshold. Mayron aprova qualquer mudança. Mudança de prompt: apenas Mayron propõe e aprova. Nenhum prompt hardcoded no código — sempre carregado do banco.
CampoDescriçãoExemplo
version_idID sequencial da versãov1.4.2
version_typeprompt / threshold / guardrailthreshold
componentQual módulo foi alteradodecision_engine · ROAS_scale_threshold
previous_valueValor anterior (JSON){"roas_scale_min": 25}
new_valueNovo valor aprovado (JSON){"roas_scale_min": 22}
proposed_byQuem propôs a mudançacassiano@ibob.com.br
approved_bySempre Mayron para promptsmayron@ibob.com.br
rationaleJustificativa da mudançaExperimentos mostraram que 22x é o threshold real da iBob
rollback_toID da versão anteriorv1.4.1
statusactive / rolled_back / supersededactive
Regra de prompt: nenhum prompt é editado diretamente no código em produção. Prompts ficam na tabela agent_versions. O decision_engine.py sempre carrega o prompt da versão com status=active no banco. Rollback de prompt é instantâneo sem novo deploy.

Processo de mudança

Mudança de threshold (Cassiano propõe)

  • Cassiano identifica necessidade com base em dados ou experimentos
  • Abre proposta no dashboard: componente, valor atual, valor proposto, justificativa
  • Sistema grava em agent_versions com status=pending_approval
  • Mayron recebe notificação e revisa no dashboard
  • Mayron aprova ou rejeita com comentário
  • Se aprovado: entra em vigor no próximo ciclo (06h)
  • Se problemas: rollback em 1 clique — versão anterior restaurada

Mudança de prompt (apenas Mayron)

  • Mayron identifica necessidade de ajuste no comportamento do Claude
  • Edita o prompt diretamente no dashboard (nunca no código)
  • Sistema grava nova versão com status=pending_approval
  • Mayron revisa e auto-aprova (ou pede revisão externa)
  • Novo prompt ativo no próximo ciclo — sem novo deploy
  • execution_log sempre registra qual prompt_version estava ativa
  • Rollback disponível para qualquer versão anterior
